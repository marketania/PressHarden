# PressHarden 0.1.2

Readable policy status, consistent command help, and a newcomer guide with
selected-source installation and practical first-run examples.

## Everyday use

- `status SITE` and `check SITE` show a combined WordPress/PHP overview. Select
  one or more areas with `-wp`, `-php`, `-updates`, and `-locks`; use `--verbose`
  for details within the chosen areas.
- Colored summaries distinguish observations, review items and incomplete
  checks. Color controls respect plain redirected output and `NO_COLOR`.
- Grouped help, topic help and `--target SITE` make common operations easier to
  find. Existing commands and guarded mutation workflows remain supported.
- The README explains requirements, selected releases, configuration, nested
  sites, result meanings, troubleshooting and recovery.

## Correctness and recovery

- Refuse unusable, syntactically invalid or failed saved configuration before
  dispatch. Preserve exact exported scope and multiline exclusions; refuse
  readonly saved values that prevent an explicit override.
- Mark failed requested detail rendering incomplete before the site summary,
  withhold partial detail output, and keep verbose results within the selected
  areas. Empty doctor scopes and invalid config roots now fail clearly.
- Validate site-bound policy records and update inventory counts; sanitize
  provider output and report unreadable lock state as incomplete.
- Inspect PHP WAF/autoload directives as inert text for status while retaining
  strict writer refusal. Correct SameSite `None` quoting and respect disabled or
  nondefault user-INI filenames.
- Strengthen transaction paths, locks and private recovery metadata against
  symlink and concurrent replacement. Keep policy previews, per-site approval,
  readback and conditional rollback, with explicit web-runtime uncertainty.

## Update

From an installed PressHarden directory, finish other operations and run:

```bash
./pressharden update
./pressharden version
./pressharden config-new
```

The ordinary updater follows moving `main`; use
`PRESSHARDEN_REF=v0.1.2 ./pressharden update` to select this release explicitly.
Private configuration and state are preserved. `config-new` previews missing
options without changing the saved file. Git checkouts are maintained through
Git; use a separate portable installation for the program updater.

There are no data migrations or new sibling dependencies. Source publication
does not change website policy or WordPress update preferences. Configured local
PHP values remain distinct from measured web-runtime enforcement. See the
[README](https://github.com/marketania/PressHarden/blob/v0.1.2/README.md) and
[update recovery guide](https://github.com/marketania/PressHarden/blob/v0.1.2/docs/UPDATING.md)
for operation and recovery details.
